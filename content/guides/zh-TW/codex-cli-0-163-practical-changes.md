[Codex CLI 0.163.0](https://github.com/openai/codex/releases/tag/rust-v0.163.0)於 2026 年 10 月 15 日釋出。對經常在終端裡使用 Codex 的使用者，值得關注的是設定查詢、任務中途補充要求，以及恢復舊對話和 Windows 貼上時的修復。

## 用 /config 找設定，留意是否需要重啟

互動對話中的 `/config` 可以跨分類搜尋偏好設定，支援的選項可立即修改，並區分哪些變化需要重啟。找不到一個開關時，可以先在這裡確認目前選項，而不是直接猜設定檔案裡的鍵名。

更新前先用 `codex --version` 看自己執行的 CLI 版本。桌面應用的版本號和終端裡的 CLI 安裝分別核對；這篇釋出說明不能直接證明桌面應用已經包含同樣的改動。

## 執行中追加要求，打斷行為更完整

該版本支援在 Codex 回答時傳送後續訊息，立即調整任務方向。比如發現修改範圍過大，可以補充“先只處理登入模組”。釋出說明還明確，打斷目前輪次會停止活動中的 Code Mode 單元及其巢狀工具呼叫。

對於已寫入磁碟的修改，仍應檢視差異後再決定下一步。更快接收糾正有助於減少繼續偏離，但一次打斷並不替代對已有成果的檢查。

## 恢復對話、Windows 與 WSL 的變化

| 場景 | 0.163.0 說明 |
| --- | --- |
| 恢復儲存的對話 | 恢復其權限和網路核准，同時遵守明確覆蓋項及目前託管策略 |
| Windows 貼上 | `Ctrl+V`、`Shift+Insert` 同時支援文字和圖片 |
| WSL 反覆貼上或複製 | 重複使用剪貼簿讀取器，複製嘗試以逾時結束，避免停滯 |
| 子程序保持輸出管道開啟 | 改善本地命令的結束行為；遠端命令保留晚到輸出供最後一次輪詢收取 |

如果你正好遇到其中一種症狀，升級後應在原來的終端、專案和操作方式下重現，確認對應問題是否消失。本文整理的是發行說明，沒有在本站環境逐項實測這些修復。

## 升級前後保留哪些資訊

記錄 CLI 版本、作業系統、啟動方式和最短重現步驟；更新後重複同一步驟。若問題只在恢復舊對話時出現，把“新對話正常、恢復對話異常”一併寫入回饋，會比只說“Codex 卡住了”更容易定位。

完整版本範圍及其他更改見[官方釋出頁](https://github.com/openai/codex/releases/tag/rust-v0.163.0)。本文聚焦 0.163.0，不將其說成所有用戶端的統一版本。
